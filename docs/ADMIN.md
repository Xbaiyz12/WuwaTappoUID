# 管理说明

`wt状态`、`wt强制更新资源` 仅限 Bot 主人或超级用户使用。

## 图片页脚

所有输出图片使用 `Powered by GsCore & Created By WuwaTappoUID Bot：飞行雪绒` 页脚。在 GsCore 后台的 `WuwaTappoUID` 插件配置中修改 **图片页脚 Bot 名称**（`bot_name`），即可替换 `Bot：` 后的名称，默认“飞行雪绒”。保存后新生成的图片及重新发送的缓存通知使用新名称，无需重启。

图鉴和背包仍按类别输出完整图片。绘图按需加载本地素材，缩放图与合成小图共享64MiB缓存，通知结果图片另有32MiB缓存上限；帮助图仅保留当前配置的一张图片。各类输出绘图串行执行，不在等待网络时占用绘图锁。图鉴等JPEG卡片保持质量90，帮助图沿用GsCore全局图片质量设置。

## 次数上限与任务时长

在 GsCore 后台的插件配置中选择 `WuwaTappoUID`：

- **单次增加次数上限**（`max_click_increment`）：正整数，默认1,000,000，仅限制手动 `wt增加次数`；自动补充仍为每次10,000。
- **宝箱任务时长（小时）**（`chest_task_hours`）：正整数，默认24，用于 `wt宝箱` 新建任务及每次续期增加的时长。

保存后无需重启。次数上限用于后续命令，任务时长用于后续新建和续期；已有任务保留原到期时间，暂停和恢复继续保留剩余时间。剩余不超过1小时仍可续期，并提醒一次。文字和图片帮助显示当前配置值；无效的非正数会明确提示修改配置。

## 导入已有登录态

一般直接私聊发送 `wt添加token TOKEN` 即可。批量导入时：

1. 首次启动插件后停止 GsCore。
2. 将 [session-import.example.json](session-import.example.json) 复制到插件资源目录，改名为 `session-import.json`。默认目录是 GsCore 下的 `data/WuwaTappoUID/`。
3. 替换全部占位内容：`platform` 为适配器的 `Event.bot_id`，`user_id` 为聊天用户 ID，`cuid` 为库洛账号标识，`domestic` 为 `1` 国服或 `0` 海外，`token` 不带 `Bearer `。
4. 启动 GsCore。插件验证账号后保存绑定，并删除已成功导入的文件；导入校验或网络失败时保留文件并提醒主人，已有账号与任务继续运行。修正文件后重启可重新导入。

导入不会自动开启宝箱任务。登录态保存在 GsCore 数据库中，不要将真实 token 或数据库提交到仓库。

可选 `expire_time` 可填写登录接口返回的秒/毫秒时间戳或日期时间。未提供期限时尝试原 token 续期，成功后记录期限；不会把导入时间当作签发时间。已知期限剩余不足2天时续期，成功延长7天，保持原 token。

业务接口拒绝鉴权后先查询账号确认；原token仍有效则保留会话。账号查询也拒绝鉴权时直接标记过期，不再自动登录。SDK新token先保存再验证，网络中断后只验证已保存的新token。

## 数据与恢复

- 更新插件后必须重启 GsCore。启动时自动补字段并校验表结构；旧字段填默认值，不回填历史账号关联或重发旧结果。数据库失败会停止插件后台任务，请检查首次异常，更新并重启。
- 数据库和插件资源目录由 GsCore 管理；备份需包含数据库与资源目录。
- 重启会恢复原任务，手动暂停任务继续冻结计时。通过 `wt恢复` 恢复，不直接修改数据库状态。
- 通知发送失败会保留并补发；不要重放开箱请求来补通知。
- 开箱汇总每页最多40件，多页合并转发；更新前已排队的整轮通知也会分页。原始流水和通知提交状态保留。
- 删除最后一条用户关联时清除该账号保存的token，开箱流水与历史通知保留；仍有其他用户绑定时保留共享账号凭据。
- `wt更新资源` 补齐素材；`wt强制更新资源` 覆盖更新素材，不清空账号或任务。
- 资源更新包含物品主图和桌宠头像。绘图只读本地缓存，缺少独立头像时按角色 ID 或素材文件名复用主图，不等待网络下载。
- 手动及自动增加次数提交前，与同账号最近一次实际网络请求结束时间间隔至少30秒。查询、背包、合成、开箱、角色查询和续期均计入；只读缓存命中不计为请求。80013最多重试3次，每次重新满足30秒间隔，始终提交同一个目标累计值；等待期间到期的任务不再提交。

## 网页登录配置

在 GsCore 的 WuwaTappoUID 插件配置中设置 `login_public_url`，填写打开登录页的浏览器能访问到的 HTTP/HTTPS 基础地址，例如 `http://192.168.1.10:8765` 或 `https://login.example.com`，不包含 `/wuwatappouid/login`。本地模式留空时按 GsCore HOST/PORT 生成 HTTP 地址；HOST为0.0.0.0或::时使用127.0.0.1作为本机入口。外置模式必须填写ww-login地址。保留原配置键名以兼容已有配置，不检测或要求公网。

本地模式的登录页与提交接口复用 GsCore，页面及接口统一位于 `/wuwatappouid/`。公网使用 HTTPS 反向代理，转发该前缀即可，其余路径返回404；不要将管理控制台和WebSocket入口一并开放。

### 本地登录（默认）

保持 `login_use_local=true`，将 `login_public_url` 指向浏览器可访问的 GsCore 地址或反代地址。本地模式指登录页面由 GsCore 提供，不要求开放公网；本机、局域网、VPN和隧道访问均可。`127.0.0.1` 指打开页面的设备自身；在其他设备上登录时应填写该设备能访问到的地址。

公网 HTTPS 反代示例：

```nginx
server {
    listen 443 ssl;
    server_name login.example.com;
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    location /wuwatappouid/ { proxy_pass http://127.0.0.1:8765; }
    location / { return 404; }
}
```

`wt登录` 在原群聊或私聊发送 `/wuwatappouid/i/{auth}` 一次性链接和二维码；同一用户的新链接取代旧链接，5分钟内有效，请勿转发。本地与外置页面都在返回HTML前校验会话并写入脱敏绑定对象和SDK配置，不再由浏览器请求status或sdk-config。仅支持国服，海外仍使用 `wt添加token TOKEN 海外`。`wt添加token` 只允许私聊使用。

浏览器通过 `/wuwatappouid/login` 提交SDK凭据，机器人随后读取会话并完成账号绑定。本地每秒读取已提交会话，临时SDK数据消费后清除。页面按WW交互显示“登录成功”弹窗，5秒后跳转WuwaTappoUID项目主页；该弹窗表示SDK登录及提交成功，最终绑定结果以机器人通知为准。登录失败、链接超时或处理被重启中断时也通过机器人通知。新token已取得但验证未完成时，机器人提示重新打开原链接点击“继续登录”，不重新交换token。

页面直接提供手机号、验证码输入框和登录按钮，浏览器按官方 KrSDK 的短信/OAuth 接口获取真实SDK凭据，再交给插件交换WuwaTappo token并验证账号。没有鸣潮角色也可以登录：按官方客户端使用角色及区服占位值0，显示“漂泊者”；渠道缺失时使用0。手机号和短信验证码直接发送至库洛接口，不发送给 GsCore 或 ww-login；需要人机验证时才打开验证窗口。页面不接收WuwaTappo token。认证请求不会自动重发；新token已取得但验证中断时，原页面可点击继续登录。

角色查询按官方客户端1.0.4携带SDK凭据的accessToken和用户名cname，取得登录所需的角色、区服及渠道字段。wt登录会保存SDK token、openid、用户名、有效期及提供凭据的用户身份，用于后续用户主动wt恢复；不保存手机号、密码或验证码，SDK token不回显到消息或日志。

每次wt信息使用平台token重新请求user/me，和EXE设置中的昵称栏一样，直接显示返回的nickname；UID、点击数和宝箱状态也来自本次账号响应。SDK登录与直接添加token使用同一套展示，不依赖SDK角色快照；0.1.42起启动迁移删除废弃的role_info、roles_updated_at列，不影响账号、token和任务数据。SDK角色查询只在登录或用户主动恢复登录时用于取得认证载荷，不缓存角色资料。

HTTP601表示官方维护。插件暂缓游戏业务请求，每分钟仅通过活动配置探测恢复；维护期间不增加后台异常次数、不冻结或延长宝箱任务期限，已保存的结果与控制命令仍保留。

### 外置登录（ww-login）

1. 部署 ww-login 0.3.2及以上版本。WuwaTappoUID 0.1.43与新版外置协议配套升级，更新后重新发送wt登录。
2. 插件配置中将 `login_use_local` 关闭，`login_public_url` 填写 ww-login 的地址，例如 `https://login.example.com`。
3. 重启 GsCore。用户仍发送 `wt登录`，使用同样的5分钟链接和二维码。

外置服务只需转发 `/wuwatappouid/`，与本地使用相同的会话页面和提交路径。插件通过POST `/wuwatappouid/token`创建会话，通过POST `/wuwatappouid/get`读取和确认结果，保留私有轮询凭证。也使用 XWUID 时，同时保留 `/waves/` 的反代。GsCore 只需能主动访问 ww-login 和游戏后端，无需公网开放自身网页或 WebSocket。

插件正常每3秒查询外置登录结果，通信失败按3、6、12、24、30秒退避，之后每30秒重试至链接到期。短暂断线不直接判为登录失败，也不逐会话给主人告警。浏览器不持有私有轮询凭证或 WuwaTappo token。

账号处理结果、失败或待验证通知以及外置待确认标记一并保存；外置确认失败时只重发已保存的结果，重启后也不重复验证或排通知。用户重新打开链接主动点击继续登录时，才开始下一次验证。

外置服务没有第二套账号库，也不执行 SDK 自动重登。服务重启导致临时会话丢失时，重新发送 `wt登录`；已保存的新token仍由插件验证，不回退旧token。提交结果不明时返回机器人查看结果，或重新打开原链接查看服务器保存的会话；待验证状态可点击“继续登录”，不会重复交换token。

## 登录态失效与任务恢复

- 账号查询确认token鉴权失效时，账号标记过期，暂停运行中的宝箱任务并通知任务用户；网络、接口格式和程序错误不会直接标记过期。
- 已过期账号的查询和游戏操作直接提示恢复方式；本人的SDK凭据完整且未到预计期限时提示wt恢复，否则仍提示wt登录或wt添加token。不在后台自动重登。
- `wt登录` 和 `wt添加token TOKEN` 验证成功后更新token，自动恢复因鉴权失效暂停、尚未到期的任务；保留原归属、计数、通知位置和剩余有效期。
- 手动暂停、其他故障暂停的任务保持暂停，需 `wt恢复`；已到期任务用 `wt宝箱` 新建。恢复失败会明确说明原因，不把登录成功报告为失败。
- 鉴权暂停不冻结计时；即使未重新登录，到期也会收尾并汇总已保存的开箱结果，不再发送开箱请求。
- `wt查看` 显示过期标记；CUID查看、切换和删除保留，`wt绑定 CUID` 及CUID自动重登已移除。

### SDK免验证码恢复

SDK期限由登录页转发auth/getToken.lg返回的expires_in，插件按接收时刻加该秒数保存；平台token使用登录响应expire_time及原有续期逻辑。未提供SDK期限的旧页面或旧ww-login不会启用SDK恢复，成功登录时会明确提示。旧账号需要一次新的wt登录以保存恢复凭据，期限不是固定写死的25天。

wt恢复先检查现有平台登录态，仍有效时继续原任务恢复流程，不重新登录；已失效且本人SDK凭据可用时查询角色并交换一次新token。新token先保存为recovering再验证user/me，验证中断后下一次wt恢复只继续验证，不重复交换。新token确认可用后恢复有权限、未到期的暂停任务；手动暂停继续保留冻结计时语义，鉴权暂停保留原到期时间。没有任务时只恢复账号，已结束或已到期任务不重新开启。

SDK凭据实际被官方拒绝时清除并要求重新登录，网络中断或维护不清除SDK凭据。通过wt添加token或导入更新本人账号时不保留本人的SDK恢复授权；另一用户提供的SDK凭据不会被当前用户用于恢复。解绑提供SDK凭据的关系或删除最后一个绑定时清除SDK凭据。重新交换平台token会使同账号其他客户端的旧登录态失效，用户主动发送wt恢复即执行此操作。

## 后台异常提醒

本地登录写入超时沿用现有后台连续失败上限和60、300、900秒退避；达到上限后停止该会话处理，并通过现有主人订阅私聊预警。停止不依赖成功写入数据库，避免数据库持续繁忙时反复处理。主人排除故障后，用户可重新发送wt登录开启新会话。

- 主人提醒用于持续的后台异常，例如缺列、程序错误、结果核对或通知处理反复失败。默认连续3轮（`retry_limit`）后提醒主人并暂停对应异常处理，避免反复刷日志；不封禁前台命令或把有效token判为过期。
- 首次保留诊断，持续错误记录次数摘要；提醒通过GS主人订阅在后台私聊发送，命令回复不等待投递。
- 提醒发送本身有限重试，仍失败只记日志，不生成递归告警；没有告警ID、人工重发或解封命令。
- 只保留待发送提醒，后台异常计数在当前运行周期内使用；重启重新监测，数据库中的token过期标记保留。旧命令封禁和告警管理状态不再使用。
